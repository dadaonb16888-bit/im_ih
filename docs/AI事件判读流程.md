# AI负责事件判读

## 当前分工

事件判断由Codex执行。用户无需选IM/IH、填写传导链或审批研究方向。程序保存Codex的结论和证据，检查输入时间、引用及正式因果资格。工作台的补充录入表单保留为资料补充/调试工具，不是用户必须完成的步骤。

Codex按原文事实→信息增量→预期基线→相对受益及反例→方向与置信度→周期→失效条件的顺序判读。资料不足也要形成明确结论：不定方向，列缺口并由Codex继续查；不把未知标成中性或把补证责任交回用户。

每条AI卡分别展示：事实及来源、AI传导推理、研究方向、增量与超预期、两指数受益解释、暴露与提前定价、冲突、失效条件、后续动作和证据核对方式。

## 研究方向和正式资格

研究倾向允许低置信度、增量未知和时间缺口，并如实显示。AI判读已完成不等于相对受益或市场已经验证。只有有明确增量基线、相对暴露、完整原文和时间，且没有待解决的方向缺口时，结果才可进一步提交正式因果更新。行情接受度及入场执行继续独立。

数据库新增`ai_research_runs`和`ai_assessments`，只追加不可改删。服务端保存实际`known_at`，重复包沿用首次时刻，不把新闻日期当研究时点。每次判读保留输入摘要与原因果版本，过时结果拒绝写入。

新增来源、判读和可选正式投影在一个事务中写入，失败全部回滚。工作台只读AI结果，未提供将任意网页JSON直接升级成正式AI判读的写接口。作者标签和摘要不能证明语义正确；来源读取和推理实际由当前Codex研究流程承担。

## 如何让Codex更新

在当前对话提出“更新事件判读”或指定事件。Codex读取上下文、联网核对、生成结构化研究包并写回系统；打开事件的“AI判读”即可查看。此流程不要求你逐项填写判断。

```text
python manage.py ai-context EVENT_ID --output 上下文.json
python manage.py apply-ai-research AI研究包.json
```

这两个命令是Codex研究与保存结果的接口，程序没有按关键词自动给方向。本地服务当前展示已保存的AI结论；无人值守模型调用和定时运行尚未接入，不会在关闭当前研究对话后自动持续判读。
