# 每日收集与分流工作台

## 使用顺序

启动`python workbench.py`，打开 http://127.0.0.1:8766/ ，点击顶部“每日收集”。

1. 创建批次。窗口按北京时间包含起点和Cutoff；默认前一自然日00:00至当前，周一扩展至上周五00:00。节后手动扩大到完整休市期并填写说明。Cutoff固定，检查更晚的信息时另建批次。
2. 检查来源。覆盖列表展示14类和26个已登记来源，按照每类入口逐项查询。登记检索时刻、实际栏目及范围、命中数、全文可读情况、证据和缺口。来源不可读或缺正文时保存“部分/受阻”，不能写“无事件”。来源中的旧检查结果不会沿用。
3. 保存信息。可新录入或把已有Inbox资料加入批次。原文发布时间决定窗口归属；日期级或未知时刻单列。首次发现时间及依据可选，服务端实际录入时刻另存，不能把当前补录倒填成历史已经知道。
4. Codex分流。由Codex判断新Parent、旧Parent Update、市场State、背景或待核实，保存理由和证据。前三种去向需要已创建的近期Parent；“新Parent”只可选择尚未完成因果审核的候选。分流只关联资料，正式因果Update/State仍分别保存。录入表单作为补充/调试工具，用户无需填方向。
5. 复核既有Parent。批次创建时固定全部未失效近期Parent名单，分别记录无新增、有新增或待核实。窗口之外的原事件仍需跟进。历史研究模板保持独立，不混入当前名单。
6. 下载批次JSON。报告包含窗口、报告生成时刻、完整信息清单、14类覆盖、分流、Parent复核、缺口和全部修订历史。

## 完成与遗漏的口径

单个登记入口只有在检索时刻不早于Cutoff、声明检查完整窗口、全文无缺口时，才可标完整。有命中须全文可读，零命中须填“未命中”。某类别的全部登记入口完成后，该类别才完成；新闻命中数不代表独立事件数量，重复原文会提示相同链接，但资料仍保留。

批次`ready`表示登记覆盖、分流、时间归属和既有Parent复核均无待办，不表示全网不存在遗漏，更不表示方向已验证或可以交易。空白批次展示14类未完成和全部Parent待复核，不能被称为“没有事件”。

原文在窗口内但之后才发现的信息保留补录标记；窗口前信息单列补录，Cutoff后的信息单列窗口后。未知公开时刻不伪造零点，发布时间修正需另录新原始信息并写明修订关系，原记录保留。

所有检查、分类修订、分流修订与复核均追加，报告取`as_of`之前最新可见记录。后续“受阻”会替代原来的“完整”状态，旧结果不会被删。批次窗口不可改写；扩大窗口请新建批次。

## 命令行与历史查询

在仓库根目录可使用：

```text
python manage.py collection-plan
python manage.py collection 批次.json
python manage.py source-check 来源检查.json
python manage.py collection-item 关联.json
python manage.py triage 分流.json
python manage.py parent-review 后续复核.json
python manage.py collection-report 批次编号 --output 批次报告.json
python manage.py collection-report 批次编号 --as-of 2026-10-13T12:00:00+08:00
```

批量接口JSON须提供唯一编号及含时区的`known_at`；工作台自动使用实际提交时刻，不接受前端倒填。字段结构可参照下载报告里的历史记录；报告时间与新闻Cutoff分别保留。

来源读取、事实核实和传导判读由当前Codex研究流程执行，详见《AI事件判读流程》。本地服务保存与展示结果；自动新闻抓取、无人值守模型、定时扫描、行情接入、回测及交易执行尚未接入。
