# 事件处理规则：落实版

## 一、依据与版本

来源：[ChatGPT《股指品种对冲策略研究》](https://chatgpt.com/c/6ac8eb59-034c-83e8-89d8-04063cc5f820)。读取接口返回最近5轮，原始返回保存在 `data/chatgpt_source_snapshot.json`；本次没有取得更早完整历史。主要依据最新两轮的《项目启动包V1.0》和补充第21—34节，以及用户提供的同版启动包。

采用更新后的事件架构。旧框架14类Category继续用于收集归档；10类Channel用于解释传导。旧Trend/Shock描述冲击形态，新Fast/Swing/Trend描述作用周期，不能按名称直接互换。1/3/15分钟与后续1/5/15分钟的执行差异本阶段不裁决。

原聊天补充称有“13个核心Event”，可读定稿实际列出11个Parent，日内瓦是关税Parent的Update。保留11个历史研究模板，不补造数量。历史阶段和方向仅是来源研究标签，未重新核实，不能当作已验证信号。旧聊天仓位与术语表述不纳入事件模块。

## 二、三个账本必须分开

**Information Inbox：原始信息。** 保存标题、原文地址、来源、公开时间、首次看到时间、原始事实、核实状态。收集时先不确定方向。一条新闻可能只作背景；多篇报道可以指向同一Parent。

**Parent Event + Event Update：独立因果及新信息。** Parent回答“正在改变哪一条IM/IH相对定价逻辑”。它可以只有数小时，不要求长期。初始创建为Draft，通过Event Update提交首次因果审核；InformationGain属于每次Update。后续新事实改变渠道或方向，仍沿用同一EventID。

**State Update：市场怎样交易这条逻辑。** 仅接收PricingState和MarketAcceptance及行情证据；不允许提交Bias、Channel、Horizon。价格反向可以令Acceptance=Rejected，但不会自动改写Bias、关闭Parent或生成反向事件。

程序不自动把新闻标题解释成事件，不使用Category固定映射方向。市场异常可以作为MarketState Parent的首次识别输入，须给出当时可观察的机制证据和识别规则；单纯上涨/下跌只能作为State。

## 三、从信息到事件的Codex判读

依据2026-10-13用户指定的分工，下列判断由Codex执行并保存，每一步保留证据，用户无需填方向。旧来源中的人工用语不再表示需要用户审核。AI研究卡与正式因果和市场确认分开，详见《AI事件判读流程》。

1. **事实是什么？** 原文是否可读，正式实施还是征求意见，发布时间、适用范围、金额及执行日期是否明确？传闻与正式公告分开。
2. **比已有预期多了什么？** 与上一次政策/公告及市场事前预期比较。High为机制或规模的重要变化；Medium为可实质改变传导的增量；Low为重复、评论或小变化。这是Codex研究标注规范，尚无统计阈值；未知可在AI账本保存为null，不为通过引擎强填Medium。
3. **是否有独立因果且影响相对定价？** 一般性经济新闻未必影响IM/IH之差。若确认没有，IGNORE；证据不足则WATCH，不能用“不知道”代替“没有”。
4. **是否属于已有Parent？** 相同因果链的新信息归并Update；独立机制才新建Parent。若只是价格反馈，转State；若只是旧信息重述，保留Inbox，必要时Low Update。
5. **谁受益更多、谁受损更多？** 写出“事实→经济/资金影响→风格差异→当期两指数暴露”。同时列IM论据、IH反例、权重与成分日期、提前定价、竞争事件、失效条件。资料不足不输出方向。
6. **作用周期是什么？** Fast：小时至数天；Swing：数天至数周；Trend：数周以上。不是持仓承诺；须有依据。
7. **市场接受了吗？** 用同步IM/IH相对价格及对应观察区间判断。没有行情不能填Confirmed，也不能默认Fresh。

InformationGain与Surprise不混同：信息有增量不代表超预期；SourceQuality高不代表方向有把握；P1/P2/P3是研究顺序，不是InformationGain或仓位等级。

## 四、渠道与方向

渠道枚举：TECH_GROWTH、DIRECT_SMALLCAP_LIQUIDITY、DIRECT_LARGECAP、MARKET_LIQUIDITY、CREDIT_LARGECAP、REGULATION_QUALITY、RISK_APPETITE、RISK_OFF、MARKET_STABILIZATION、POSITIONING。允许多渠道，第一个为主渠道；每次方向变化要说明哪个机制占优及其新增证据。

Bias：Strong IM / IM / Neutral / IH / Strong IH；未知为null。StyleSignal依次为+2/+1/0/-1/-2，D取符号；强弱标签不代表已验证的仓位倍数。初始Bias由首次有依据的标注确定，之后当前Bias可经Update改变，初始值仍保留。

Directness由Codex研究标注1—3：1为间接宏观链条，2为较明确行业/配置传导，3为直接影响对应指数成分资金或交易结构。必须写依据；不按Channel机械赋值。

## 五、资格与主导事件

资格依次判断：独立因果和相对定价影响→至少Medium增量→完整方向/渠道/周期→MarketAcceptance→PricingState。

|输出|含义|
|---|---|
|WATCH|内部补充状态：待审核、缺时间或状态、市场尚未确认，包括Rejected；暂停新开|
|IGNORE|审核后无独立相对定价价值、只有Low信息，或Neutral|
|TRADEABLE|事件资格通过，Confirmed且Fresh/Diffusing；不是开仓指令|
|LATE|Crowded/Reversing阶段，暂停新开，保留原始因果方向|
|INVALID|新的因果信息明确使逻辑失效，不由单纯价格反向触发|

方向切换后，切换之前的行情确认不沿用，需重新提交当前方向的State。Low重复报道不抹掉仍有效的最近一次Medium/High增量；后续Medium会替代High，不永久取历史最高分。因果失效为终结状态，由Codex重新评估新的独立逻辑，不允许一条价格记录重启。

主导事件采用保守实施口径：仅从当前TRADEABLE事件中选取。Fast/Swing/Trend分别输出Intraday/Swing/Trend。周期内按Directness→最近有效InformationGain→Acceptance排序，不加权求和。相同优先级方向相反则冲突待裁决；同方向同级多个候选也不任意选一。未审核历史模板不会参与。

这是V1工程选择：相较原框架先选主导再择时的抽象描述，本模块输出“通过事件资格的主导候选”；尚未确认的强事件仍在WATCH池展示。未来若需“研究主导事件”和“可参与主导事件”双输出，可单独扩展。

`entry_allowed`始终false，因为技术入场和硬风控不在本阶段。Diffusing是否最好、直接度和接受度排序是否有效，都仍需后续验证。

## 六、时间与审计

公开/识别时间event_time；最早可交易时间first_tradable_time；事实或状态发生时间effective_at；该判断可获得时间known_at；实际写入时间recorded_at。完整时间必须含时区。日期级历史标签留在历史模板，不能伪造零点。

历史查询同时限制effective_at与known_at均不晚于as_of。10月11日才作出的解释不能以10月9日新闻发布时间倒填成10月9日已知道。已有研究迁移按实际迁移时间入库；原判断时间完整保留在legacy中，但未验证为当时可用，不直接激活历史信号。

SQLite启用外键；事件、更新、状态、原始信息和旧审计只追加，不覆盖删除。程序严格分开因果更新和State输入；重复ID内容不一致会拒绝。原文语义与传导证据由Codex实际读取和研究，不能仅靠填写source_type或actor证明有效。
