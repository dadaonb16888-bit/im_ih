# 每日收集与审核流程

## 1. 时间窗口

每次记录北京时间Cutoff。默认收集**前一个自然日00:00至当前Cutoff**，不是仅前一个交易日或几条热点；沿用已有收集口径，周一及节后额外补齐整个休市期并明确起点。以原始发布时间归入窗口，同时记录首次发现时间。时间未核实的列入“时间待核实”，不伪造精确时刻。

每次同时重看全部未失效Parent的后续进展，即使Parent起点在窗口外。迟到信息另标“补录”，不因窗口外而遗失；已收信息按ID与原文链接查重，同事件多来源保留交叉核实但不计作多个独立事件。

## 2. 14类覆盖检查

沿用 `analysis/ih_im_event_research/sources.json` 的具体来源登记，不因只收到某几类信息就删掉其余类型。

|Category|必查内容|来源层级/入口类型|
|---|---|---|
|TECH|产品、研发、技术突破、实际订单及产业传导|公司/科研机构原文，产业权威报道|
|POLICY_GROWTH|财政、投资、消费及民营支持的增量和实施对象|国务院、发改委、财政部、商务部|
|MONETARY|利率、准备金、净流动性及信用条件变化|央行、官方金融数据|
|REGULATION|交易、退市、IPO、基金、融券等制度|证监会、交易所、行业监管公告|
|FUND_FLOW|ETF、险资、公募与长期资金配置|官方披露、基金公告、可核实流量数据|
|SMALLCAP_LIQUIDITY|集中赎回、去杠杆、可成交性及小盘结构异常|交易所/基金披露与同步行情；无单一新闻可用MarketState|
|RISK_OFF|贸易、地缘、信用、系统性风险的新事实|官方当事方、权威通讯社原文|
|RISK_ON|风险解除、谈判结果、信用和流动性修复|与原冲击Parent的公告及进展对照|
|VALUE_DIVIDEND|银行保险、央企、高股息与分红配置变化|公司、基金、国资与险资正式公告|
|BROAD_STIMULUS|货币财政资本市场组合政策及阶段扩散|多个官方政策原文，不重复计数|
|SEASONAL|假期、年末、财报季的可观测背景|交易日历、历史统计；单独不创建方向事件|
|POSITIONING|套保、拥挤、集中仓位和去杠杆|中金所、持仓及成交数据；估计与已知事实分开|
|EARNINGS|业绩、订单、盈利预期差及成分暴露|交易所和公司公告；个股不等于指数|
|EXTERNAL_MACRO|海外利率、通胀、美元和全球流动性|海外央行/统计机构/权威通讯社|

每类记录“查过的来源、检索时间、命中数、全文是否可读、缺口”。空白不是无事件。只有扫描完成才可写“该窗口未发现相关新增”；网页打不开写“未完成覆盖”，不能宣称没有。

## 3. 日内处理顺序

1. **收齐Inbox**：原始事实与评论分开；官方原文优先；重要报道追溯原出处。不要先凭方向筛掉反方信息。
2. **去重和归并**：相同新闻不重复建Parent；判定新Parent、旧Parent Update、市场State、背景/重复、待核实五种去向。
3. **先审事件资格**：新增多少、独立机制、相对暴露、初始渠道、Horizon、失效条件。研究优先级与因果方向分别记录。
4. **再审Bias**：同时列IM解释和IH反例，检查预期、PreMove、当期指数成分、反向事件。不确定则null/WATCH。
5. **行情单独审核**：仅已有同步数据时提交State，记录观察区间、相对价格计算、阈值/判断方法、数据来源。判断方法未量化也须写明为人工标注。
6. **输出当前报告**：各Parent资格、三周期主导候选、同级冲突、缺口与下一触发点；不输出自动进场建议。

## 4. 每天应留五份结果

完整信息清单；14类覆盖与遗漏表；Parent归并/更新清单；方向和反例审核卡；市场状态及主导候选报告。

已有资料的审核顺序可参考P1/P2/P3，但收集覆盖不受优先级限制。没有硬性“只收10条”或“只保留3个事件”的上限，也不为凑数量建立独立因果不足的Parent。
